# T-169 — iMessage relay channel adapter (done)

Builder rounds: 2. Commits d64faad, 57b872f. Decision D-050.

- Vendor-neutral relay core (`packages/adapters/src/channel/relay/`) with thin Photon and Sendblue modules written from their public docs.
  - Inbound: a signed webhook receiver bound to 127.0.0.1 maps messages, tapbacks, replies, joins and leaves, and images to channel events. Idempotent on vendor message ids.
  - Outbound: text, PNG images (QR codes), tapbacks, and `fallbackText` for rich cards. Retries are allowed only where they're safe, and outbound respects T-071 pacing.
- `config.ts` is the only file that calls `fetch`. It goes live only when `TRAV_CHANNEL=imessage_relay`, `TRAV_RELAY_LIVE=1`, a key and `TRAV_RELAY_LINE` are all set; otherwise it uses the mock relay. The simulator relay path is always the mock.
- `pnpm relay:dev` runs the simulator UI over the mock relay. The Barcelona demo passes 58 of 58 over Photon and over Sendblue, and the Razzmatazz QR codes go out as PNG DMs to exactly the five.
- Contract tests per vendor on fixture payloads. The fixtures were reconstructed from the vendors' docs, not recorded, so re-record them before going live. docs/RELAY.md covers setup and known gaps.
