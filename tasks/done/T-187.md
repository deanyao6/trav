# T-187 — BlueBubbles vendor module (dogfooding only) (done)

Builder rounds: 2. Decision D-052. Docs: docs/DEPLOY_IMESSAGE.md, docs/RELAY.md.

- Third pure vendor module on the T-169 relay core:
  - a webhook with a `?token=` shared secret (constant-time; a URL-safe secret is required for live);
  - text/react/reply sends by `chat_guid`, and tapbacks mapped to reactions;
  - QR codes uploaded directly, never via the media host.
- Relay-level "@trav" for every vendor: the iOS mention picker (BlueBubbles) and `TRAV_RELAY_CONTACT_NAME` (a leading name followed by punctuation or a request word, never inside quotes).
- Dedupe goes through an injectable seen store (the SQLite store is T-185). Pacing counts wire sends; the BlueBubbles daily cap is 150.
- Tests:
  - contract tests on reconstructed payloads (`fixtures/relay/bluebubbles/`);
  - a fake-server test with a fetch spy that must never be called;
  - the Barcelona demo at 58/58 over the BlueBubbles mock, and also plain, over Photon and over Sendblue.

All fixed in r2. r2 also changed T-071 pacing: a retryable first-try failure is now queued for every channel.
