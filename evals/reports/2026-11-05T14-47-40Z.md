## Root-cause hypotheses

1. **Rule readers were tuned on the fixture's exact lines.** N1, N2, T-192 and the held-out Lisbon gaps share one pattern: the offline rule readers (`parseSuggestAsk`, the vibe-answer binder, `booking/request.ts`) pass the phrasings their scenarios use and miss nearby paraphrases. The held-out score (96.0%) sits 3.8 pts below the dev "ready" score (99.9%), which points the same way.
2. **Scenario values chosen inside the no-op band.** `tier_private_budget_soft` uses a figure that maps to the default tier, so it passes whether the private signal is ignored or applied. Scenarios that test "X must not change Y" need an X that *would* change Y if the guard were missing.
3. **Expense amount extraction accepts a bare integer with no currency or spend verb** (N5), probably because "the four of us" supplies a party and makes the line look like a split.
4. **Option lists are built from raw activities**, with no de-duplication by start time or booking (N6).
